# Managed hosting for Phases 1-2, planned migration to a separate server later

Hosting could be a managed platform (Vercel/Supabase) or self-hosted (Hetzner/Coolify); self-hosted is cheaper at scale and gives control over data residency, but costs solo-founder time to operate. We're starting on Supabase for the backend/database and Netlify for the frontend through the early phases, to maximize build speed while the founder builds solo. The plan is to migrate the site off Netlify onto a separate server once the product is validated, before Phase 3 commercial launch — by then usage is real and the Egypt PDPL legal opinion (OQ-04) should have clarified any data-residency requirements that could shape where that server lives.

The Supabase project exists and is empty as of 11 September 2026: project ref `skgetonknlshzrvykrpf`, API URL `https://skgetonknlshzrvykrpf.supabase.co`, PostgreSQL 17, region `eu-central-1` (Frankfurt). That region is the concrete form of the OQ-04 risk, since candidate data sits on EU rather than Egyptian infrastructure. The original plan treated this as deferrable because Phase 1 would run on test data only. That is no longer true: ADR 0003 puts real pilot-company CVs into this instance during Phase 1, with the pilot acting as data controller, so the residency question needs written legal confirmation before Phase 1 validation begins rather than before Phase 2.
