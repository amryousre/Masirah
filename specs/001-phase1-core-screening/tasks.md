## Format: `[ID] [P?] [Story] Description`

- **[P]**: Can run in parallel (different files, no dependencies)
- **[Story]**: Which user story this task belongs to (US1, US2, US3, US4)
- Exact file paths are in every task description

## Path Conventions

Per the Project Structure decision in plan.md: one repository, three top-level directories, no monorepo tooling.

- `web/` — Next.js App Router, TypeScript 5.x, Node 24 LTS
- `pipeline/` — Python 3.12 worker, `src/masirah_pipeline/`
- `supabase/` — migrations

Both runtimes carry the same `domain/`, `ports/`, `adapters/` shape. That repetition is deliberate: it is what lets domain rules in either runtime be tested without a database, a network or a model provider.

## The sequencing constraint that overrides convenience

quickstart.md is explicit: **build the accuracy suite first, before the interface.** research.md records that no real Egyptian CV has yet been run through any extraction pipeline, which makes the 95 and 85 percent targets aspirations rather than measurements. If they are unreachable the extraction approach has to change, and that is far cheaper to discover with nothing built on top of it. T028 and T029 therefore sit in the foundational phase, and T037 gates User Story 1.

## Dependencies and Execution Order

### Phase Dependencies

- **Setup (Phase 1)**: no dependencies, start immediately
- **Foundational (Phase 2)**: depends on Setup. **Blocks every user story**
- **User Stories (Phases 3 to 6)**: all depend on Foundational
- **Polish (Phase 7)**: depends on the user stories being complete

### User Story Dependencies

- **US1 (P1)**: starts after Foundational. Depends on no other story. This is the entire product loop, and nothing else in Phase 1 has value without it
- **US2 (P2)**: starts after Foundational. Genuinely separable, since US1 is viable on native files alone. Shares the worker and review queue with US1 but is independently testable
- **US3 (P2)**: starts after Foundational, but the bias suite needs scoring to exist, so it ranks below US1 in practice. Ranked below US1 only because there must be a ranking before there is a ranking to audit
- **US4 (P3)**: starts after Foundational. Ranks last because the earlier stories can be built and tested against anonymised data before any pilot data arrives

### The one ordering that is not negotiable

T028 and T029, the corpus and the accuracy harness, come before the interface work in Phase 3. quickstart.md states the reason plainly: if the accuracy numbers are unreachable the extraction approach has to change, and that is far cheaper to discover with nothing built on top of it.

### Within Each User Story

- Tests are written and observed failing before implementation (Constitution I)
- Domain before ports, ports before adapters
- Adapters before the worker loop that orchestrates them
- Server routes before the pages that call them

## Implementation Strategy

### MVP first (User Story 1 only)

1. Complete Phase 1: Setup
2. Complete Phase 2: Foundational, including the corpus and accuracy harness
3. **Stop and check the accuracy numbers.** If native PDF extraction cannot approach 95 percent, change the extraction approach now, while nothing is built on it
4. Complete Phase 3: User Story 1
5. **Stop and validate**: run quickstart scenarios 1, 2, 6 and 7
6. This is the demonstrable product. A pile of CVs becomes a defensible ranking

### Incremental delivery

1. Setup plus Foundational → foundation ready
2. Add US1 → validate → this is the MVP and it already replaces the spreadsheet the BRD names as the real incumbent
3. Add US2 → validate → photographed CVs stop falling out of the pipeline
4. Add US3 → validate → the ranking becomes defensible rather than merely produced
5. Add US4 → validate → real pilot data can lawfully enter the system
6. Phase 7 → the budgets and the accessibility gate

### A note on staffing

plan.md is written for one part-time developer. The parallel markers above describe which tasks are independent, not an expectation that several run at once. For a solo build, read [P] as "safe to reorder" rather than "do simultaneously".
